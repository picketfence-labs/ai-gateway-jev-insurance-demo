# ADR 0002: 毎ターンの事実取得と文脈に基づく追加確認度

日付: 2026-10-06。状態: 継続承認された実装方針。実モデルの判定品質は未確認。

## 背景と採用理由

旧版は3ケースと同一事実スナップショット比較を持ち、問い合わせ中の早期連絡希望を優先度に使っていた。現在の用途は、10個の合成レコードについて、取得した事実と問い合わせの組み合わせが受付判断にどう影響するかを確認すること。比較専用経路と優先度の表現は、この用途を誤解させるため撤廃する。

## 決定

- ケース選択は請求または申込の固定ルートIDを選ぶ。問い合わせ文から顧客を検索しない。
- 各新規ターンは新しい台帳を作り、当該ルートと、そのターンのAPI応答で発見した参照IDだけを使ってGETする。申込は3種類、請求は4種類の必須レコードを照合する。
- 正常なLLM完了後の不足分補完は既存のラッパーと台帳を使い、取得者を「アプリによる評価準備」と表示する。LLM失敗時の補完は禁止する。
- 比較チェックボックス、親スナップショット、比較ストア、スナップショット由来のツール応答とテストを削除する。同じ問い合わせの再評価も新規ターンなら再取得する。
- 同一リクエストIDの保持期間内再送は既存の再送防止台帳で再実行しない。これは新規ターンと異なり、永続的な冪等性ではない。
- 表示だけ最新ターン順にする。内部履歴は時系列順を維持し、元のターン番号を変更しない。LLMに渡す直前の同一ケース会話は未検証の文脈であり、事実取得の代わりにしない。
- 基準を `insurance-intake-v2` に更新する。ネイティブの `desk` / `priority` / `next_check` キー、Choiceの候補、Score型は維持する。UIでは `priority` を「追加確認度」と呼ぶ。

## 追加確認度の意味

| 段階 | 定義 |
|---|---|
| 0 | 問われた投影項目について、取得記録の限定的な説明が可能で、同一項目の相違申告がない |
| 1 | 内訳、時期など投影にない詳細の確認が必要だが、同じ記録項目・値への明示的な異議はない |
| 2 | 利用者が同じ投影項目・値の相違を明示し、人が未解決の申告差を照合する必要がある |

Scoreは0〜2の連続実数であり、段階への完全一致を合格条件にしない。早期連絡希望は緊急度を証明しない。2も真の矛盾・誤記の確定ではない。受付先と次の確認事項は、ケースIDや単一キーワードではなく、取得した事実と今回の問い合わせの両方を使う。ケース別固定正解分岐を設けない。

請求額と支払記録額の差だけで不足払いと断定しない。未記録 `null` を0円に変換しない。「支払済」は銀行入金確認ではない。否認理由、適格性、支払判断、補償の確定、契約有効性を投影から捏造しない。

## 証拠と版の境界

リクエストと結果に実際の基準版を保持し、古いv1結果をv2の尺度で説明し直さない。保存済みv1のリクエスト・応答・実測証拠は変更しない。Jevの返却値とLLM補足を分離し、Jev内部根拠を生成しない。

10ケースのレコードと参照は既存seedから投影する。seed変更、投影項目追加、APIやdata plane変更、認証変更、実モデルPOSTはこの実装に含めない。モックで得た想定結果は、実Jevの品質証明ではない。

## 影響と検証

新規ターンはGET・LLM・Jevの実行費用が発生し得る。比較専用のゼロGET経路はなくなる。リプレイ防止と試行計数は維持し、ネットワーク総数・請求金額の上限とは呼ばない。
